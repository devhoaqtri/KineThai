- Answer language is chosen per request from the Host header (lib/target-language.ts; decks in data/<locale>/); one deployment serves every language domain because Lovable has no per-project build vars. Unknown hosts (Pages, Vercel, localhost, previews) default to Japanese; `anh`/`hoa`/`han`/`nhat` keep their explicit decks.
- Public leaf page metadata uses the shared sitePageHead helper with request-resolved locale; browser-only pages use data-only SSR so domain titles are correct before hydration.
- An internal key or id never reaches a reader: `t()` and the label helpers (lib/i18n.ts) fall back to whatever they were given, so a missing entry fails silently as `difficulty.vo-long.label` or `general`. Never cast with `as CopyKey`, which is what lets a wrong key compile; a new deck topic or palette needs its vi, ja and th label. lib/__tests__/ui-copy.test.ts checks all of this against the shipped decks.
- Kinetic word entrances (framer-motion) must go through usePausableEntrance and the per-page entrance clock in WordSequenceText; framer-motion has no pause, so plain animate props keep playing under overlays. A Japanese page reveals mora by mora, never one whole 文節 at a time: WordSequenceWord splits each 文節 with kinetic-text getJapaneseMoraTokens into per-glyph JapaneseMoraSpan children on one page-wide cascade (playback-timing getMoraDelay), while layout, phraseEdges, chunk pagination and emphasis all stay per-文節 — do not collapse the split back to a whole-word pop. A Japanese page's duration counts morae as reading load, 1.5 to a Vietnamese syllable, through the same formula as every language (playback-timing getPageDuration): timing it from the cascade or from 文節 rushes readers, since a clue is only about five 文節. A page of 20 or more morae is split in two at the `|` that leaves the sides most even, or a clause end when no `|` works (ja-text paginateJapaneseChunks, which also counts morae because its 文節 budget can't see a thirty-character line); one that still can't split gets ×1.5 time. A page only runs longer than that when the cascade itself needs it.
- Deck text joins the syllables of one word with a single `_` (`ba_lô`); lib/word-joiner.ts turns it into a no-break space when a catalog loads, so the underscore never reaches a reader and the word is never split across lines. Generators and reviewers write the underscore (rules and a paste-in prompt: docs/word-joiner-generation-handoff.md); nothing downstream should strip it from stored decks.
- Japanese 0B multi-level decks import once with `--pack <stem>` and fan out to one flat pack per level (`<stem>-jprim` … `-jcoll`, ids `<word>-<level>`); `--level <CODE>` imports one. Bundled packs recover the English CEFR level from the `<cefr>-j<level>.json` filename into `word.cefr`; `mergeCatalogs` keys Japanese entries by headword+level, but feed pagers expose one card per headword (JHIGH preferred) and count unique headwords.
- The title difficulty picker always uses the English CEFR usage tracks (A1–C2, overlapping bands), including on the Japanese deck; Japanese school levels are a separate reader filter. The feed's deck locale is `settings.targetLanguage` when set (sent to `/api/public/vocabulary` as `locale`), otherwise the host-resolved locale. For Japanese, `settings.japaneseLevel` seeds only the exact level filter; the CEFR difficulty track is independent and never overwrites it (nor the reverse). Japanese school codes (`JPRIM`/`JSEC`/`JHIGH`/`JCOLL`) are internal ids and must never appear in reader-facing UI.
- Vietnamese clue pages are laid out from measured widths (post-player useMeasuredLines + kinetic-text solveMeasuredLines), not the character-count estimate; the estimate only seeds the first, unseen pass. The reader treats a word ending in `,` `.` `;` as a phrase edge (its equivalent of the generator's `|`): never break a line or page one word before or after it (docs/phrase-break-reader-handoff.md).
- Reader-imported packs (lib/custom-pack.ts) live only in browser localStorage and are paged client-side through the shared pure lib/paging.ts; fetchVocabularyPage short-circuits to them, so imports never touch the server or cloud storage.
- The memory sheet (RecallSheet, opened from Settings' history cells) must never look a past word up in a catalog: that would put every deck on the feed's first download (feed-bundle.test.ts). It reads on-device copies taken when a view is logged (lib/recall-words.ts), which keep each reader language's authored gloss, since the UI language can change after the view; a word with no copy shows `recallFallbackLabel`, which strips the school level from a Japanese id.
- The `outline` emphasis effect (hollow `-webkit-text-stroke` that fills with ink, `.kinetic-emph-outline`) reads as one clean shape only on closed-contour glyphs, so it is restricted to Japanese characters (kana or kanji); kinetic-text/lib/emphasis.ts `restrictOutlineToJapanese` runs at both render sites (WordRenderer + WordSequenceWord) and downgrades a non-Japanese token to `color` (same recolouring and shadow, no hollow stroke) — a composed shape like the digit 4 otherwise shows its detached segments.
- A Vietnamese author mark glows exactly as written, growing only from one syllable to the whole `_` word around it (post-player/lib/feed-emphasis.ts). A page with no mark keeps the neighbour compound repair, capped at two syllables, because KineThai's Vietnamese clues rarely carry `_` joins: without it "công an" glows only "an". `check:emphasis-runs` proves this on every shipped page, read in Vietnamese.
- An earned badge waits in the on-device inbox (lib/badge-inbox.ts) until its celebration has played out: the stores mark it earned at once, so never show one straight from hook state, or a reload or a reader looking away loses it for good. The close timer only runs while the page is visible.
- Word grammar (plural, verbInfo, governs, counter, hanViet, tipVi…) is written flat on generated cards, `null` where it does not apply, and folded by normalizeDeck into one optional `word.grammar` (lib/grammar.ts); the meaning panel's collapsed grammar section ("Nâng cao" / ui-copy `grammar.title`) renders it generically from that table, so a new key or value needs a gloss entry there (vi, ja and th), not new UI (docs/word-grammar-fields.md).
- A pale card (measured `tone: "light"`) highlights a clue word in its own palette accent (lib/card-emphasis cardEmphasisColor, passed as `accentColor` and used exactly), never the player's backdrop pick, which lands on near-black and reads as the ink set bolder. Its pool drops the effects drawn in light (glow, halo, sweep, flash: the pale-card rule strips text-shadows and a pale backdrop swallows white) for an accent underline and box. Deep cards keep the player's pick and the style's pool unchanged.
- A word enters the viewing history (and the memory sheet, and level progress) only once it is fully viewed: its answer page has held the screen for VIEW_ANSWER_MS (lib/history) while the page has the reader's attention, with nothing covering the feed (VocabularyCard onViewed). Attention (lib/page-attention) is the one pause signal for every clock that must not run unseen: the page hidden, frozen or cached, or on a touch-only device the window's focus taken by the system (notification shade, Control Center, a system alert, an answered call's banner) or the music paused by something other than the player (lib/ambient pauseHandler: a call ringing in a banner takes no focus, and the system pausing the audio is its only trace, so it is seen only while the music is on). A desktop blur never pauses, since the window is still on screen, and nothing else may: a touch or key on the page, focus or visibility returning ends it.
- The memory sheet is a non-modal dialog inside the settings panel: the panel's close button and any tap outside close the panel, sheet and all. Never make it modal, which disables everything outside it.
- A share link (`/w/<code>`, from the meaning panel's share button) opens the feed itself on that word, played from its first clue like any other, then the reader's own stream (VocabularyFeedPage `sharedCode` → VocabularyStream `lead`). It is fetched before the stream mounts, so it is the first word on screen; it is always shown, even if seen today; one stream only takes it, so a new level or the stream after the picker opens on its own words. No separate challenge page: the link preview is the site's own and the message never names the word.
- A share code may not read as an English word or a taboo shorthand (scripts/lib/share-code-screen: 0/1/V read as O, I/L, U for words; leetspeak and sound-alikes for taboos, English and Vietnamese). A failing code is retired, never recycled: it moves to data/share-codes-retired.json, its word gets a fresh code (scripts/rescreen-share-codes.ts), and an old link still opens the word. `npm run check:share-codes` holds it; the screen's lists stay in scripts, never in src. A wider scan is handed off in docs/share-code-screen-handoff.md.
- The first-visit badge rotates through BADGE_ROTATION (lib/badge-variants — aurora, glass, mint, sunrise) by stream position so neighbouring words never share one; compared at /badge-lab.
