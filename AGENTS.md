- Answer language is chosen per request from the Host header (lib/target-language.ts; decks in data/<locale>/); one deployment serves every language domain because Lovable has no per-project build vars.
- Public leaf page metadata uses the shared sitePageHead helper with request-resolved locale; browser-only pages use data-only SSR so domain titles are correct before hydration.
- Kinetic word entrances (framer-motion) must go through usePausableEntrance and the per-page entrance clock in WordSequenceText; framer-motion has no pause, so plain animate props keep playing under overlays.
- Deck text joins the syllables of one word with a single `_` (`ba_lô`); lib/word-joiner.ts turns it into a no-break space when a catalog loads, so the underscore never reaches a reader and the word is never split across lines. Generators and reviewers write the underscore (rules and a paste-in prompt: docs/word-joiner-generation-handoff.md); nothing downstream should strip it from stored decks.
- Vietnamese and Han clue pages are laid out from measured widths (post-player useMeasuredLines + kinetic-text solveMeasuredLines), not the character-count estimate; the estimate only seeds the first, unseen pass. A Han page keeps dictionary words whole (getHanWordSpans, Intl.Segmenter) and its phrase edges are only a preference (softPhraseEdges), so a wide blank beside a comma cannot size the whole page. The reader treats a word ending in `,` `.` `;` as a phrase edge (its equivalent of the generator's `|`): never break a line or page one word before or after it (docs/phrase-break-reader-handoff.md).
- A Vietnamese clue page (lead, definition, anticipation) glows only what the deck wrote inside `/…/`, as exactly two syllables connected with `_` or `=` (lib/highlight-gate.ts, run per page in buildStages). A connector alone never glows: `_` also stops a line break, so joins do not prove a word and nothing may pick a highlight from them. Lone syllables, unconnected pairs and three syllables are refused even when marked, and a page with no passing mark stays dark: `dataEmphasis: []` means nothing glows, so never add a fallback for it; the fix is a mark in the deck. Generators follow docs/highlight-generation-rule.md. `npm run check:emphasis-runs` proves it on every shipped page and fails if dark pages rise above MAX_DARK_CLUE_PAGES: lower that number as decks improve, never raise it.
- Reader-imported packs (lib/custom-pack.ts) live only in browser localStorage and are paged client-side through the shared pure lib/paging.ts; fetchVocabularyPage short-circuits to them, so imports never touch the server or cloud storage.
- Internal bot table reads must remain limited by the existing system-account policies or privileged server access; never restore unrestricted authenticated SELECT policies, because posting configuration and run history are not public feed data.
- Word grammar (plural, verbInfo, governs, counter, hanViet, tipVi…) is written flat on generated cards, `null` where it does not apply, and folded by normalizeDeck into one optional `word.grammar` (lib/grammar.ts); the meaning panel's collapsed "Nâng cao" section renders it generically from that table, so a new key or value needs a gloss entry there, not new UI (docs/word-grammar-fields.md). Opening it by hand holds that word's card and is never remembered; only the Settings choice (`presentation.expandGrammar`, shown on non-English hosts) carries across words, and it doubles the answer page of a word that really shows the section, never any other page.
- The memory sheet (components/RecallSheet.tsx) opens from a settings memory cell through hooks/useRecallZoom and fills the settings panel, never the screen: every moving part is a Web Animation on one shared clock, so closing mid-flight reverses and a pull-down scrubs the same playhead; the sheet's natural state is fully open, and it never scales or reflows text. Each row answers with its own check and cross, and shows only the short meaning while SHOW_WORD_DETAILS is off. It reads on-device word copies (lib/recall-words.ts, taken when a view is logged) because decks are server-only: never import lib/catalog-source into a client component. The build fails if one does (scripts/deck-guard-plugin.ts); `npm run check:deck-not-bundled` is the deeper check after a build.
- Export is a local admin tool that runs from `npm run dev` and never on the hosted site. Export Studio, `/export/$code`, `/showcase`, `/carousel/$code`, `/api/dev/carousel`, the community post recorder and vocabulary-export.css sit behind `import.meta.env.DEV`, so a production build answers 404 and carries none of them; admin visibility goes through `useCanExport`. Import these only behind that check: the build fails if one reaches a bundle (scripts/deck-guard-plugin.ts).
- A carousel slide is the reader's VocabularyCard told to start on one page with nothing playing (`exportLayout.still`), never a recording stopped at the right moment; a fixed delay cannot prove a page is finished. lib/slide-settle.ts proves it instead and fails with a reason. Fonts load before the card mounts, because the measured layout steps down and never back up. Layout is always 432 CSS px wide at 2.5×, so a new shape is one row in lib/carousel-formats.ts. `npm run carousel <code> -- --twice --seams` and `npm run check:carousel-fit` are the proof after a change.
- Word reports and hiding run per deck, because word ids are only unique within one (`budget` is German and French). The deck comes from the Host via deckLocaleFor, so a language with no deck of its own counts as English. A word leaves that language's feed at 2 different readers picking a severe chip or 3 reporting it for any reason (lib/word-block.ts); a reader is a salted address digest, so a null never counts. The served revision folds in that deck's blocklist digest with no separator: revisions travel back as bounded hex, and any other character ends every feed at page one.
- The word library (/admin/library) browses the decks readers are served, one language at a time: level folders open as 50-word tables swiped sideways (SwipePages, native scroll snapping). Its navigations pass `resetScroll: false`, because the router's scroll restoration otherwise drags the strip back mid-slide. The editor reads and writes raw deck files (api/deck-files.server.ts), never the loaded catalog, which has already turned `_` into no-break spaces. Saving works only under `npm run dev` and every save re-validates the whole file through normalizeDeck. A word-crawler re-import replaces these files, so a lasting fix belongs in that deck too.
